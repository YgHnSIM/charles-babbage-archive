# Git 커밋 메시지 규칙 (Commit Message Convention)

본 프로젝트(Charles Babbage Digital Archive & Exhibition)의 Git 커밋 메시지 작성 표준 가이드입니다.
일관성 있는 커밋 로그를 유지하여 변경 이력을 쉽게 파악하고 협업 및 유지보수 효율을 높이는 것을 목적으로 합니다.

---

## 1. 커밋 메시지 기본 구조

커밋 메시지는 기본적으로 **Conventional Commits** 표준을 따르며, 다음과 같이 `Header`, `Body`, `Footer` 3개 영역으로 구분합니다.
(Body와 Footer는 선택 사항)

```
<type>(<scope>): <subject>

<body>

<footer>
```

- **Header**: 변경 사항의 성격(`type`), 영향 범위(`scope`), 간결한 요약(`subject`)을 한 줄로 작성 (필수)
- **Body**: 변경 이유와 상세 내용 설명 (선택)
- **Footer**: 이슈 번호 참조 및 주요 호환성 변경(Breaking Change) 명시 (선택)

---

## 2. Type (타입) 목록

| 타입           | 설명                                                           | 예시                                                        |
| :------------- | :------------------------------------------------------------- | :---------------------------------------------------------- |
| **`feat`**     | 새로운 기능 추가                                               | `feat(timeline): 찰스 배비지 생애 인터랙티브 타임라인 추가` |
| **`fix`**      | 버그 및 오류 수정                                              | `fix(viewer): PDF 1차 사료 뷰어 확대/축소 오류 수정`        |
| **`content`**  | 사료 해제, 기사, 텍스트 등 아카이브 콘텐츠 추가/수정           | `content(engine): 차분기관 1호 해제 및 기술 분석 문서 추가` |
| **`source`**   | 1차 사료(PDF) 파일 추가 또는 수집/동기화 스크립트 수정         | `source: 1864년 자서전 Passages 원문 PDF 추가`              |
| **`docs`**     | 문서 추가 및 수정 (README, ADR, CONTEXT 등)                    | `docs(adr): 0004번 아카이브 검색 엔진 ADR 추가`             |
| **`style`**    | 코드 스타일/포맷팅 수정 (동작 변경 없음, 세미콜론/들여쓰기 등) | `style(ui): 메인 헤더 CSS 정렬 및 여백 조정`                |
| **`refactor`** | 기능 변경 없는 코드 리팩터링 및 구조 개선                      | `refactor(astro): 사료 카드 컴포넌트 모듈화`                |
| **`perf`**     | 성능 최적화 (로딩 속도, 번들 크기, 이미지 최적화 등)           | `perf(image): 고해상도 도판 WebP 변환 및 레이지 로딩 적용`  |
| **`test`**     | 테스트 코드 추가 또는 기존 테스트 수정                         | `test(sync): 사료 메타데이터 유효성 검증 테스트 추가`       |
| **`chore`**    | 빌드 설정, 패키지 매니저, 환경 설정 등 기타 작업               | `chore(deps): Astro 4.x 최신 패치 버전 업데이트`            |

---

## 3. Scope (영역 - 선택 사항)

변경이 발생한 모듈/도메인 영역을 괄호 `()` 안에 명시할 수 있습니다.

- `engine`: 차분기관 / 해석기관 관련 시뮬레이터 및 뷰어
- `archive`: 1차 사료 데이터 및 아카이브 시스템
- `timeline`: 연대기 / 생애 타임라인 컴포넌트
- `ui`: 공통 레이아웃, 네비게이션, 스타일 컴포넌트
- `adr`: 아키텍처 결정 기록(ADR)
- `sync`: 사료 수집 및 메타데이터 동기화 스크립트 (`sync_sources.py` 등)
- `deps`: 라이브러리 및 의존성 패키지

## 4. 세부 작성 규칙

### 4.1. Subject (제목)
- **50자 이내**로 명확하고 간결하게 작성합니다.
- 끝에 **마침표(`.`)를 찍지 않습니다**.
- 한글 작성 시 **명확한 명사형 종결** 또는 **간결한 종결형**(예: `~ 추가`, `~ 수정`, `~ 개선`)을 사용합니다.
- 영문 작성 시 **명령문/동사 원형**(예: `Add`, `Fix`, `Update`, `Refactor`)으로 시작하며 첫 글자는 대문자로 시작합니다.

### 4.2. Body (본문)
- 제목만으로 충분히 설명하기 어려운 복잡한 변경이 있을 때 작성합니다.
- **"어떻게(How)"보다는 "무엇을(What)"과 "왜(Why)" 변경했는지**에 중점을 둡니다.
- 한 줄당 **72자 내외**로 줄바꿈을 권장합니다.
- 여러 항목을 나열할 때는 하이픈(`-`) 글머리 기호를 사용합니다.

### 4.3. Footer (바닥글)
- 관련 Issue 번호나 Breaking Changes를 기록합니다.
- 예: `Closes #12`, `Fixes #34`, `Refs #56`
- 하위 호환성을 깨는 변경이 있는 경우 `BREAKING CHANGE: <설명>` 형태로 기재합니다.

## 5. 커밋 메시지 예시

### 예시 1: 신규 기능 추가 (Header + Body + Footer)
```
feat(engine): 해석기관 천공카드 시뮬레이터 UI 구현

- 작전 카드(Operation Cards) 사칙연산 선택 패널 추가
- 변수 카드(Variable Cards) 스토어 레지스터 연결 시각화
- 캔버스 기반 밀(Mill) 기계 회전 애니메이션 연동

Closes #15
```

### 예시 2: 아카이브 사료 콘텐츠 추가 (단일 라인)
```
content(archive): 1843년 에이다 러브레이스 주석(Notes A~G) 영문/국문 해제 추가
```

### 예시 3: 버그 수정
```
fix(sync): 대용량 PDF 다운로드 시 타임아웃 발생하는 현상 해결

- requests 세션 재시도(Retry) 백오프 로직 적용
- 청크 단위 스트리밍 다운로드로 메모리 점유율 개선
```

## 6. Git 커밋 템플릿 적용 방법

프로젝트 루트의 `.gitmessage.txt` 템플릿을 Git 설정에 등록하여 커밋 시 가이드를 편리하게 확인할 수 있습니다.

```bash
# 로컬 저장소에 커밋 템플릿 등록
git config --local commit.template .gitmessage.txt
```
